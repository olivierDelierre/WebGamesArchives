# MotionBall 2 – HTML5 port

A port of Frutiparc's MotionBall 2 (Flash / ActionScript 2, 2004) to plain HTML5 canvas and JavaScript. It has no dependencies and no build step.

## Playing

The best way is to serve the folder over HTTP:

```sh
cd Frutiparc/Games/motionBall2/html5
python3 -m http.server 8000   # then open http://localhost:8000
```

Opening `index.html` directly from disk (`file://`) also works. In that case sounds play through `<audio>` elements, because Web Audio can't fetch local files, so the layered in-game music may drift slightly out of sync.

Controls:

- **Arrow keys / WASD (ZQSD on AZERTY):** roll the ball
- **Space:** switch to another ball
- **Esc / P:** pause, and show the map once you've found it
- **Mouse:** menus

On touch screens, drag on the game to roll the ball; buttons below the game switch balls and pause.

Progress is stored in `localStorage`: unlocked courses and dungeons, course records, best scores and TItems.

## Game modes

All modes of the original are available:

| Mode | Levels |
| --- | --- |
| Challenge | random 8×8 dungeon: find the balls, beat the octopus |
| Aventure | the 5 hand-made dungeons (`../dungeon/adv_*.txt`): 4 elemental snakes and the final boss |
| Course | the 7 circuits (`../dungeon/course_*.txt`) against CPU records; beating a record unlocks the next course |
| Classique | endless descent through randomly generated rooms |
| Aide | the tutorial dungeon (`../dungeon/tuto.txt`) |

In the original, the Frusion client (the Frutiparc "disc") could lock some modes. Here every mode is available, as with a "white disc".

## How it was ported

| Original | Port |
| --- | --- |
| `mb2/*.as` (game logic) | `js/game.js`, `js/boss.js`, `js/screens.js`, `js/main.js`: close, line-by-line ports keeping the original names and constants (40 fps logic, same physics, collision sampling and boss AI) |
| `mb2gen/*.ml` (OCaml generator of `.dat` files) | `js/data.js`: the dungeon/room generator (`dungeon.ml`, `level.ml`) is ported to JS and runs in the browser for Challenge and Classique; `assemble.ml` is used to load the hand-made dungeons |
| `ext.util.MTBitcodec` | `js/data.js` (`MB2.BitCodec`): base64 alphabet `a-zA-Z0-9-_`, MSB first |
| `../dungeon/*.txt` | `js/levels.js`, generated by `node tools/build_levels.js` |
| bitmaps and sounds inside `mb2.fla` | `assets/`, extracted by `tools/extract_fla.py` (FLA lossless bitmap format, raw PCM sounds) plus `../sounds/*.wav` |
| vector symbols inside `mb2.fla` | redrawn with the canvas API in `js/gfx.js` and `js/gfx_boss.js` |
| MovieClip timelines | `MB2.Clip` in `js/core.js`: a tiny frame/label/action timeline, so the AS code (`gotoAndPlay("hit")`, `_currentframe == 1`, …) ports as-is |

### Known differences

- **Redrawn art:** the vector art (balls, most bumpers, doors, bosses, effects) can't be read out of the binary `.fla`, so it was redrawn to look like the original. The backgrounds, menu balls, bumper parts, snake boss and help pictures are the original bitmaps.
- **Hitmaps:** collision maps of the bumpers come from `mb2gen/bumpers.txt`. For the switch, zapper and item box they are approximated by circles.
- **Final boss animations:** the timeline animations of the final boss ("Tourneboule") were rebuilt. Its callbacks (`animDone`, `kataDone`) fire at the same points of its behaviour.
- **Zapper beams:** these are drawn faintly so the player can see which ball colour crosses them.
- **Online features:** online rankings are replaced by local records.

See [FLA_DECODING.md](FLA_DECODING.md) for how to decode the vector art of the `.fla` files and where to plug it in.
